# AI 交接说明

更新日期：2026-11-08。接手时先读本文件、根目录 AGENTS.md、windows/README.md；详细设计在 docs/architecture.md。

## 运行与目录

- 仓库： https://github.com/AllToBeNize/neko-player ，Windows 代码在 windows/，Android 仅占位与方案，尚未开发客户端。
- Windows：Tauri 2 + Rust + Vue 3 + TypeScript + Vite，WebView2 音频，Rust 本机媒体代理。
- 启动：在 windows/ 执行 npm install、npm run desktop。需要 Rust MSVC、VS C++ Build Tools、WebView2。desktop 脚本补充 Cargo PATH。
- 前端构建：npm run build --prefix windows。Rust 检查：cargo check --manifest-path windows/src-tauri/Cargo.toml。
- 当前使用开发窗口，没有生成正式安装包；无托盘、完整系统媒体键或独立原生音频引擎。
- SQLite 在 %APPDATA%/com.alltobenize.neko-player/library.sqlite；登录 Cookie 和 AudD Token 在 Windows 凭据管理器。不要把真实数据库、凭据、日志提交或输出。

## 重要限制与后续工作

1. 用户实际要识别电脑正在播放的音频。WASAPI Loopback 尚未实现，不能把当前麦克风功能说成系统音频采集；下一步应加 Windows 输出设备回环捕获，再交给识曲服务。
2. AudD 需用户自己的 Token，存在服务额度/费用；不支持哼唱。不要声称已有无 Token 识曲或离线识曲。
3. 翻译来自歌词内附译文或用户导入；无机器翻译。无逐字时间轴时只做逐行，不用平均字长假装演唱对齐。
4. B站 code=0/data.v_voucher 也是验证要求；首次发现即暂停搜索并持久化，通过官方页面由用户完成。不能靠匿名切换、轮换账号规避验证。
5. 官方字样是标题线索，不是已核验账号认证；完整1091首匹配准确率没有验收。接口会变化。
6. 本地文件保存元数据/队列，重启需重新选择文件恢复授权；不能持久保存 blob URL。
7. Android/iQOO Neo11 OriginOS7 原子随身听调研见 docs/originos7-integration.md，不要当作已实现集成。

## 文件与数据约定

- App.vue：主状态、播放协调、IPC、曲库保存、队列与菜单、设置连接。目前较大，后续可谨慎拆分，先保住持久化和异步代次保护。
- SettingsPanel.vue：受控设置 UI；SourcePicker.vue：候选、评分、独立版本保存表单；TrackDetails.vue：歌词和逐曲音量。
- matching.ts / music-names.ts：MATCH_VERSION=5、版本意图、别名和搜索构造。manual 映射不可被升级自动覆盖。
- track-versions.ts：version:UUID 独立身份，根 parentId/baseTitle、referenceTitle、searchTerms；不复制旧 hash/歌词/偏移/URL。
- track-audio.ts：trackAudioSettings 稳定键；酷狗按hash共用，独立版本按新ID隔离。
- audio-balance.ts：分析→自动增益→手动增益→压缩→主音量；手动增益不能被自动平衡抵消。不是 LUFS 标准化或真峰值保证。
- queue-history.ts：entryId 区别重复歌曲。cursorId/positions/pending 都按 entryId；排序不换ID、不重播。下一首复用队列项，不复制。
- 最后一项被用户移除时保留 cleared=true 的空会话；compactSessions 保留该显式空状态，避免启动从历史误恢复。不要删除这个标记或放宽意外空队列保护。
- Rust playback_store：CAS revision + SQLite immediate transaction，禁止旧状态覆盖，保留5份备份。读取失败不允许用空数据自动覆盖。
- lyrics.ts / KaraokeLine.vue：字时钟、文件offset、译文；Rust krc.rs / lyrics.rs：受限解压与独立歌词缓存。
- Rust main.rs / web_login.rs / search_response.rs / search_verification.rs / kugou.rs / suggestions.rs：平台服务与代理。

## 最新修正：点歌与评分一致性

普通用户点歌/队列点击/上下首通过 startEntry 的 fromStart=true 从头播放；历史会话切回、暂停继续和换源重载仍可续播。检查点保留，不等于每次点击都从检查点开始。手动映射也参与分数重算，保持 BVID/manual 身份不变；SourcePicker scores 事件同步匹配当前选定 BVID 的分数，不能拿排名第一的分数替代已选源分数。同步按歌曲ID+BVID双重检查，避免试听或历史旧源的分数覆盖另一音源。

队列拖动已从原生手柄拖拽改为整行 Pointer Events：350ms长按或7px移动激活，指针捕获追踪，elementFromPoint定位插入行，RAF处理边缘滚动。pointerup提交，pointercancel/失去捕获取消；卸载清理计时器、RAF和捕获。更多按钮不参与拖动，拖动后抑制click避免误播放。队列行设置touch-action:none，触屏在歌曲行上用于拖动而非原生纵向滚动，可通过面板其他区域/滚动条滚动。

音量平衡继承：全局 defaultBalanceEnabled 作为默认；trackAudioSettings[key].balanceEnabled 仅在用户手动操作单曲开关时写入。缺省/只有gainDb不算自定义。详情的「跟随全局」删除 balanceEnabled 字段并保留 gainDb，严禁全局切换时遍历覆盖各曲设置。旧存档已有显式开关仍视作自定义。

队列外观修正：移除左侧拖动图标列，仍支持整行拖动。新增 QueueCover.vue，在序号与歌名之间显示42px歌曲封面；优先队列封面，旧队列缺失时从曲库/历史补取，图片缺失或加载失败显示音乐图标。图片禁用原生拖动以保留整行Pointer拖动行为。

歌词匹配已更新：Rust lyric_match.rs 是独立纯评分模块，lyrics.rs 最多4次串行去重搜索并汇总候选，强匹配提前退出，仍使用KRC/LRC下载及LRCLIB备用。TrackDetails 自动传 titleAliases/artistAliases，复用 music-names 的外来语和歌手别名，调用 get_lyrics 的新增参数均为Option，旧调用可兼容。缓存命名空间 alias-scored-v3。匹配门槛：标题相似度>=0.88，非空歌手列表至少一项>=0.88，已知时长差<=15秒；不同乐器/现场等版本拒绝。按60/30/10评分而非直接放开substring。字幕译文仍只来自歌词数据，没有机器翻译。已验证截图标题/多歌手及跨文字别名的正例和错误歌曲/歌手/时长/版本反例；平台查询未保证此曲收录。日志不要输出歌词全文或下载accesskey。

加入歌单定位：已存在项不再禁用，显示「已在歌单，点击定位」，打开目标歌单并滚动/高亮对应歌曲；新增歌曲也自动定位，关闭队列和详情避免遮挡。仍按ID去重，不复制已有条目。已用300首列表验证新增末尾定位和已存在项无重复定位。用户反馈的MAD视频已在真实库中，未修改其已有记录。

歌单新增项改为头部插入（加入歌单、搜索添加、收藏、独立版本、本地批量新增；批量内部保留选择顺序），已有项不重排。右下角新增定位正在播放/回到顶部固定按钮；优先当前列表定位，否则打开包含歌曲的歌单，其次最近播放，最后队列。定位只滚动高亮，不调用播放，不重置进度。详情/弹窗/队列展开时隐藏快捷浮栏，避免遮挡。已验证300首歌单头部插入、末尾定位、回顶且无音源解析/重播。注意早先交接文档提到的新增末尾定位行为已由本次头部插入替代。

歌源搜索现在优先去掉括号译名，用原文名构造关键词；独立版本与钢琴/现场/Live等版本标签保留，不降低版本约束。preferredSearchTitle仅改变搜索词，不修改显示标题，titleAliases仍保留括号别名参与评分。可完整识别的片假名外来语仍可搜索英文拼写；带版本标签时不因英文转换丢失版本信息。已检查用户截图日文名、括号英文别名、版本保留与空标题回退。

歌源通用检索算法：新增 source-search.ts，统一供导入自动匹配、点歌即时匹配和换源搜索使用。music-names.sourceSearchQueries生成最多5组去重策略：优先原名/英文外来语、原文字形、拆分歌手、仅歌名、其他别名。各轮按BVID合并后统一55/35/10评分，只有score>=85且歌手/歌名分均>=88才提前退出；改编等弱候选会继续下一策略。附加轮次相隔4秒，取消后不再请求，任何平台验证/网络错误直接上抛，不尝试切词绕过验证。用户手动输入不同关键词时尊重该查询。已有可靠缓存不强制重新联网；点击搜索使用通用流程。查询改进不会强制覆盖已有手动歌源。已通过模拟平台返回验证弱候选扩展、合并去重、排名、可靠结果早停、取消和验证中止；不是对整份歌单真实匹配率的验收。

评分第五版修正合集误判：不再因「歌单」「日推歌单」「单曲循环」等宣传词直接扣分；仅明确合集/串烧/medley/compilation、明确小时循环等线索触发合集降权，时长偏差继续独立检查。MATCH_VERSION=5，旧评分刷新，人工选择不自动替换。已验证宣传词反例与明确合集/长循环正例。
