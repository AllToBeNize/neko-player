# Neko Player 技术说明

状态：Windows 第一版已实现并启动；Android 仍为技术设计。更新：2026-11-07。

## Windows 第一版实现状态

当前运行方式及功能边界见 [Windows README](../windows/README.md)。已实现 Tauri 窗口、Vue 界面、SQLite 歌单持久化、B 站扫码入口及搜索、AAC 音轨解析、基于本地流代理的 WebView2 音频播放、歌曲清单导入和人工换源。

原生独立音频引擎尚未落地：为先交付可体验版本，第一版用 WebView2 audio 播放，Rust 代理负责流请求及 Range 转发。下文 Symphonia + cpal 为后续目标。酷狗短链接及 global_collection_id 分享格式已实现，并以用户提供的「嗝」歌单验证完整导入 1091 首，持久化后数量一致。其他分享格式仍需分别验证；元数据导入不表示所有歌曲已经匹配到 B 站音源。

补充功能：搜索支持 BV 号和包含 BV 号的视频链接直达；听歌识曲采用 AudD 官方 API，需要用户自己的 Token。支持麦克风和文件片段，上传前明确告知，最多提交 12 秒 WAV，Token 通过 Windows 凭据管理器保存，不共享 B 站客户端或 Cookie。识曲结果再交给 B 站搜索，不能把识别出的歌名直接当成已验证音源。原曲识别不等于哼唱识别；后者不在首版范围。AudD 完整识别链路尚待实际 Token 验证。

## 结论摘要

Windows 优先采用 Tauri 2 + Vue 3 + TypeScript + Rust，后续 Android 采用 Kotlin + Compose + Media3。两端共享业务协议及数据语义，分别实现平台播放和系统集成。首版不需要自建服务器。

核心可行性要通过小规模端到端原型验证：酷狗歌单读取、B 站登录与搜索、候选匹配、音频播放。现有参考代码不等于接口已在本项目验证通过。

Android 目标设备为用户确认的 iQOO Neo11，系统为 OriginOS 7，完整构建版本待真机验证时记录。原子随身听接入调查及验证计划见 [OriginOS 7 适配说明](originos7-integration.md)。当前没有查到其公开专用 SDK，不能承诺自动进入音源列表。

## 目标与范围

先实现 Windows：酷狗分享歌单元数据导入 → B 站登录 → 候选视频搜索和歌曲匹配 → 本地歌单 → 在线音频播放。
“创建歌单”暂指应用本地歌单，不自动修改 B 站收藏夹。首版只播放视频音轨，不实现视频画面或下载。

## 建议技术栈

- Windows：Tauri 2；Vue 3、TypeScript、Vite、Pinia；Rust、Tokio、reqwest。
- 音频：Symphonia 解码 + cpal 输出；先验证 B 站实际返回的编码和流式跳转，再决定是否补充 FFmpeg。音频播放独立于 WebView 生命周期。
- 数据：SQLite / rusqlite，保存歌单、歌曲、来源映射、匹配状态、播放历史及队列。
- 凭据：Windows Credential Manager / keyring。前端不持久化 Cookie，日志脱敏，支持退出和清除凭据。
- Android 后续：Kotlin、Jetpack Compose、Media3 ExoPlayer + MediaLibraryService / MediaLibrarySession、Room。MediaLibraryService 同时承载后台播放与媒体库浏览。共享数据模型和接口约定，暂不引入 Rust JNI。
- 首版无需自建服务器，平台请求在本机执行，账号凭据留在设备。

## 关键设计

模块职责：UI 只操作应用服务；应用服务编排导入、匹配及队列；酷狗、B 站适配器封装平台访问；数据库保存业务状态；播放器仅接收已经解析的可播放资源。平台接口变化应尽量限定在适配器内部。

酷狗适配器负责分享文本提取、短链接展开、歌单标识解析、分页及歌曲元数据归一化。是否需要酷狗登录、链接是否完整可读，需要真实链接验证；不能预先保证所有分享格式可用。

B 站适配器负责登录、会话验证、搜索、视频分 P 和播放地址解析。现已提供扫码及隔离的官方网页登录窗口，支持用户在官方页面选择密码或短信方式。官方网页登录窗口打开后，前端每两秒顺序检测，Rust 在异步命令中读取 Cookie，用独立 HTTP 客户端验证账号，验证成功才保存到系统凭据并用于应用请求，随后自动关闭官方窗口、更新播放器账号。登录窗口不授予应用 IPC 权限，采用隐私模式，不收集账号密码或短信验证码。平台接口、签名、风控与会话行为可能变化；实际密码/短信登录成功链路仍需用户完成登录后验收。

匹配使用歌名、歌手、时长及版本词综合评分；对翻唱、现场、混剪、合集等降权。默认选中综合分最高的候选，用户可右键试听和替换。任务支持取消、限速、重试及断点继续，不保证一一匹配。

歌曲原始身份与播放来源分开保存。记录 BVID、CID、分 P、匹配理由和人工选择；播放 URL 按需解析，不能作为永久地址。失效后重新解析并保留原曲信息。

## 数据模型与跨端边界

| 实体 | 关键字段与用途 |
| --- | --- |
| Track | 内部 UUID、歌名、歌手列表、专辑、时长毫秒、原平台及原平台 ID |
| Playlist / PlaylistItem | 歌单 UUID、名称、歌曲引用、顺序；允许导入结果中存在未匹配歌曲 |
| SourceMapping | Track UUID、BVID、CID、分 P、匹配方式、置信度、用户锁定标记、验证时间 |
| ImportJob / ImportItem | 导入来源、分页进度、每曲匹配状态、失败原因、重试次数 |
| PlaybackState | 队列、当前位置、循环模式、最近播放位置 |

自动匹配不得覆盖用户锁定的音源。保留源歌曲信息，换源只修改 SourceMapping；导入重试不得重复创建同一个任务内已成功保存的条目。

跨端导出采用带 schemaVersion 的 JSON，约定 UUID、毫秒时长、UTC 时间及字符串形式的平台 ID。可导出歌单与音源映射，不导出 Cookie、临时播放 URL 或设备密钥。跨端云同步暂不实现。

## Windows 实现约束

Vue 页面通过明确的 Tauri command 接口调用 Rust，不接触 Cookie 和任意系统命令。外部链接解析须校验协议与主机，限制跳转次数、响应大小和超时；平台请求与媒体流地址分别校验。

音频首期验证 AAC/M4A 等实际返回格式、边下载边播放、暂停、拖动、自动下一首，以及地址过期后的恢复。未通过验证前不承诺无缝播放、无损格式或全格式支持。需要 FFmpeg 时另行确定打包体积和许可要求。

数据库升级采用版本迁移；平台适配返回区分登录失效、限流、资源不可用和网络错误。日志避免写入 Cookie、授权头及包含敏感参数的完整 URL。

## 自动音源匹配实现

导入完成后自动排队搜索当前歌单；旧歌单提供「自动匹配音源」。归一化后按歌手信息、歌名相似度和时长分别以 55/35/10 加权，版本不一致及过大时长差降权。依据 2026-11-08 用户要求，存在候选即默认写入最高分结果的 BVID；实际点击播放时解析音轨及检查权限；不保存易失效播放 URL。

每首保留匹配状态、置信度、解释和至多八个候选。人工确认标记 manual，后台不覆盖已存在的 BVID；待确认条目可直接展示缓存候选并试听选择。取消后忽略在途结果；串行请求间隔至少 1.6 秒，连续三次异常暂停。匹配结果通过现有 SQLite 歌单存储持久化，完整 1091 首歌单的准确率尚未评估。
## 播放交互与状态

播放模式使用 PlaybackMode 单一枚举，顺序播放在队列结尾停止，列表循环回到首曲，单曲循环重播当前曲，随机模式避免立即重复同一曲；用户指定的下一首优先于这些模式。音量内部为 0–1，界面百分比为 0–100，输入边界限制和显示同步，连同播放模式持久化。

歌源更换保留原歌曲身份、歌手与原始时长，更新 BVID 及评分并标记 manual；背景匹配不覆盖人工选择。播放中的歌曲换源会刷新当前音轨，点击歌曲自身直接播放，右键与行内操作不会触发额外的行点击播放。所有界面验证文件均在项目外临时目录完成并清理。
## B 站搜索验证状态

不能仅用 code=0 判断搜索成功。data.v_voucher 或平台风控码表示验证要求，缺少 result 数组表示异常返回，都不得转换成空曲库。安全验证触发后第一次即停止批量查询；通过官方页面按用户操作完成验证后，再用同一接口确认恢复，不采用匿名切换或账号轮换规避验证。待验证状态随本地偏好保存，退出账号时关闭验证窗口。

## 同步歌词与播放详情

TrackDetails 使用当前歌曲及 HTMLMediaElement 的 elapsed 驱动歌词。lyrics.ts 解析多时间戳 LRC、同一时刻双语歌词及文件 offset，二分查找当前行；正的用户偏移表示歌词延后，同样应用于点击行后的播放跳转。手动滚动暂停自动跟随五秒，可点击回到当前歌词。歌词换曲与异步查询使用代次校验，避免上一曲结果覆盖当前曲。

Rust lyrics 模块单独请求歌词服务，不携带 B 站 Cookie。按来源 hash、歌名、歌手和时长匹配，成功结果存入独立 lyrics_cache 表；网络错误不写入负缓存。无匹配、纯音乐和纯文本是不同状态。手工导入及重新匹配的选择作为歌曲自定义歌词保存。

## 主题与音量处理

四套浅色主题使用统一 CSS 变量管理强调色及背景色，当前歌词使用深强调色。主强调色与白色按钮文字对比度至少 4.5:1，播放模式保持无选中背景块。

音频链为媒体元素 → 分析器 → 自动增益 → 动态压缩 → 用户主音量 → 输出。RMS 滤波、静音门限、增益边界及渐变时间共同限制突变，不宣称 LUFS 标准化或真峰值限制。所有歌曲复用同一 AudioContext；换曲重置自动增益，暂停不更新估计，关闭功能绕过自动增益和压缩，卸载释放音频节点和计时器。媒体元素使用 anonymous CORS，Rust 本机代理在已注册 UUID 媒体流响应上提供 CORS 支持。

## 搜索推荐

SearchInput 同时用于顶栏和发现页，history/library/music/remote 四类候选经统一归一化去重。仅聚焦的组件请求在线建议；输入防抖与请求代次校验防止结果乱序，IME 输入期间不提交搜索。Rust suggestions 模块访问 B 站公开 suggest 接口，隔离账号凭据，缓存带 TTL、数量上限，接口异常不会影响主搜索与播放。

## 历史队列与插队

QueueSession 保存 id/name/entries/cursorId/positions/pending/mode/updatedAt，每个 QueueEntry 拥有独立 entryId、track、inserted 和 addedAt。进度按 entryId 存储而非歌曲 ID，避免同曲重复出现时互相覆盖。单击歌曲默认插入并播放，关闭插入开关才替换；显式播放歌单建立新会话，历史按最近使用保留十份。

startEntry 统一处理队列内切换、插队、历史恢复及换源，加载元数据后恢复位置。原曲被打断前先保存位置；异步请求沿用播放代次保护。保存独立 playback_state 表，运行时约五秒检查点，结构变更合并后写入，暂停、拖动、切歌及正常关窗进行即时保存。关窗通过 onCloseRequested 等待保存后销毁主窗口，重启只恢复显示不自动出声。

队列序列化去除 URL 和歌词/候选大字段，保留本地音频元数据及进度；用户重选文件后按曲名及大小重新关联。手动插入项在当前列表和历史概要中均可识别；pending 使用 entryId，优先于随机和单曲循环。

## 启动恢复与持久化保护

恢复偏好 restoreProgress 默认 false，启动保留 cursorId 对应歌曲，显示 elapsed=0，音频不自动加载播放；true 时显示旧进度。startupResumePending 与 hasStartedPlayback 区分恢复展示和真实播放，避免仅打开/关闭应用就用零进度覆盖历史。用户主动拖动进度或实际播放后才更新该项检查点。

playback_store 通过 SQLite immediate transaction 和 expectedRevision 比较写入，拒绝过期客户端以及空队列覆盖非空记录。每次正常写入保存之前的非空快照，最多五份。查询错误和损坏 JSON 返回错误，前端不会设置为可自动保存状态。正常恢复读取当前存档，异常空状态尝试快照；确无队列时从最近播放重建并标记 recovered，不伪造未保存的原顺序或进度。

## 逐字时间轴与翻译

歌词查询优先下载 KRC，经 Rust 解码 krc1/XOR/zlib 数据；解码前后均限制体积。逐字查询使用新缓存命名空间，避免已有 LRC 缓存掩盖可用的逐字歌词。无 KRC 时沿用 LRC 与 LRCLIB 回退。

lyrics.ts 解析 KRC 行起点、每字相对起点和持续时间，以及 language 元数据中的译文；KaraokeLine 使用真实时间比例填色，TrackDetails 在播放期间通过 requestAnimationFrame 读取 HTMLMediaElement.currentTime，暂停时跟随保存的 elapsed。歌词文件 offset 和用户延后设置同样应用于行定位、字进度和点击跳转。没有逐字时间的数据保持逐行显示，不推算虚假的字级对齐。

译文默认显示在原文下，可关闭；原始译文来自歌词数据，不发送歌曲内容到新的机器翻译服务。支持手动导入时间轴一致的中文 LRC，或与原文行数相同的纯文本译文；未对齐时提示且不覆盖。customTranslation 随歌曲保存，队列快照去除歌词大字段并从曲库/历史记录恢复。译文按行跟随，不伪造译文字级演唱时间。

## 音源评分第三版与跨文字别名

music-names.ts 负责搜索空白规范化、歌手别名、括号英文名提取及片假名外来语分词。外来语仅在整个名称均能由词典覆盖时生成英文别名，使用记忆化回溯处理不同词长，不以罗马字字符串强认英语语义。默认搜索可用的英文拼写，人工换源可切回原名；仍为每首一次搜索，沿用验证暂停与请求间隔。

matching.ts 将歌名主体与各别名分别评分；英文外来语别名乘 0.94，括号英文别名乘 0.92，原名精确包含保留完整证据。基础 55/35/10 之外，匹配一致的官方标题标记加 7 分，翻唱/乐器改编/现场等不一致版本降权，多种版本取最大惩罚而非重复累扣；不同乐器分开检测。分数截断到 0–100 后，同分仍优先有官方线索的版本。官方标记仅是标题证据，不宣称账号认证。标题实体解码与 BVID 去重在排序前处理。

MATCH_VERSION=3 触发已有自动候选本地重排，不访问新接口；manual 映射不覆盖。新搜索和重新搜索使用新关键词构造。缓存中不存在的候选仍须用户主动重新搜索获得，不将旧的八个候选当成完整曲库。片假名词典与歌手别名字典是可持续补充的数据，并非任意日语/英语通用翻译或已验证的全曲库匹配模型。

## 逐曲音量记忆

track-audio.ts 定义稳定歌曲键及持久化载荷校验，保存 trackAudioSettings[key] 的 balanceEnabled/gainDb。酷狗 hash 排除歌单位置，直接 B 站资源使用 BVID，本地文件使用曲名与文件大小，其他曲目沿用原始 ID。音源替换不改变酷狗曲目的音量身份。历史和队列使用独立歌曲副本，也从同一设置表读取；设置表随 save_library 的 JSON 载荷写入 SQLite，正常关闭等待已有保存任务。旧版 balanceEnabled 仅作为默认值保留，切换歌曲不会把上一首的开关写成下一首的设置。

App 的 balanceEnabled/trackGainDb 根据当前键计算，用户修改只更新对应项；同步 watcher 和 startEntry 在加载音频前应用设置。AudioBalance 使用独立歌曲 GainNode，范围 −12 至 +12 dB、约 40 ms 平滑，与自动增益和主音量分离。自动分析点仍位于所有增益之前。切曲 reset 只重置自动估计，不清空歌曲增益。压缩器在自动平衡开启或手动正增益时启用；自动平衡关闭且正增益时采用 0 dBFS/零 knee，其他关闭状态 ratio=1。它是动态压缩保护，不是严格的真峰值限制器。

## 独立版本身份

track-versions.ts 生成全新 version:UUID 歌曲，显式挑选可复用字段而非展开复制旧对象。version 元数据保存 parentId/baseTitle/name/referenceTitle/searchTerms；从版本继续另存时复用根 parentId 和 baseTitle，避免标题无限追加。手动选中的 BVID 固定为初始歌源，时长来自候选，原曲 hash、临时地址及歌词大字段不复制。source=version 使 trackAudioKey 使用新歌曲 ID，避免同曲 hash 共用原曲音量；队列 entryId 与歌曲新 ID 共同区分播放状态。

SourcePicker 发出 version(candidate,name,playlistId) 事件，App 验证目标歌单并以根 parentId+BVID 拦截同歌单重复版本，保存后打开目标歌单；现有手动换源行为保留。版本数据随曲库与队列原有 JSON/SQLite 存储，无新增平台请求或数据库迁移。

MATCH_VERSION=4 对有 version 的曲目使用 baseTitle 比较歌名，用 referenceTitle/name 区分期望版本；已有不一致版本惩罚之外，对缺失目标版本特征的候选降权。具体乐器明确时，cover 和通用演奏标签不作为额外必需条件。sourceSearchKeyword 用基础歌名加提取的版本词构造搜索；人工改名不会丢失保存时识别到的演奏类型。独立版本标记 manual，升级评分不自动换源。

## 统一设置入口

SettingsPanel 是受控组件，通过事件更新 App 原有主题/队列/音量默认偏好；持久化仍分别使用 library.preferences 与 playback_state，不在组件内另建存储。账号区域不再直接弹账号或登录，改为统一设置，未登录用户在设置进入官方登录流程。底部当前歌曲更多按钮使用 cursorId 定位重复队列项并复用上下文菜单。
