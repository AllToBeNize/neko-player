# OriginOS 7 原子随身听适配调查

调查日期：2026-11-07。目标：让 Neko Player Android 在用户的 OriginOS 7 手机上被原子随身听发现，并显示歌曲信息、响应播放控制。
当前仅完成公开资料调查；尚未连接手机、编写 Android 原型或验证真机行为。

目标设备由用户确认：iQOO Neo11，OriginOS 7。完整系统构建版本、底层 Android 版本、ROM 区域及原子随身听版本待真机验证时补充。机型信息不代表已通过适配测试。

## 调查结论

本次在 vivo 开放平台、官方帮助及公开搜索中，未查到面向普通第三方播放器、可直接下载的“原子随身听接入 SDK”、公开注册 API 或 OriginOS 7 专用接入规范。此结论表示公开证据不足，不代表 vivo 没有合作伙伴接口或登录后文档。

可以确定的是 Android 有标准媒体会话及媒体库接口。项目应先实现这些接口，以具备系统媒体控制、外部浏览和控制器连接能力。原子随身听是否使用这些接口、是否过滤包名或要求合作接入，公开资料尚不足以确认。

因此当前可承诺完成标准 Android 媒体适配；“进入原子随身听可选音源列表”“由其浏览本应用歌单”“原子岛展示”分别列为待真机验证的能力，不将其中一项成功视为其他项已支持。

## Android 设计调整

采用 Kotlin + Jetpack Compose + Media3 ExoPlayer，播放服务直接使用 MediaLibraryService 与 MediaLibrarySession，兼顾后台会话及歌单浏览；Room 保存歌单与恢复状态。

服务清单同时声明以下发现 action，兼容 Media3 和旧平台浏览客户端：

```xml
<service
    android:name=".playback.PlaybackService"
    android:exported="true"
    android:foregroundServiceType="mediaPlayback">
    <intent-filter>
        <action android:name="androidx.media3.session.MediaLibraryService" />
        <action android:name="android.media.browse.MediaBrowserService" />
    </intent-filter>
</service>
```

以上为设计片段，不是完整可运行清单。实现时补齐适用 Android 版本的前台服务权限、网络权限及启动流程，并按实际 targetSdk 核对要求。

媒体库建议以 root → 歌单 → 歌曲组织，提供媒体库根、子项分页、按 ID 查询和播放解析。mediaId 使用稳定内部标识，不暴露含鉴权参数的链接。外部点播进入本应用服务后，再由 B 站适配器解析音源。

所有播放入口使用同一播放器和队列。向会话同步标题、歌手、封面、时长、位置和播放状态，声明实际支持的上一首、下一首、暂停和跳转动作；不提供无实现的按钮。封面从本应用缓存读取，避免外部控制器依赖 B 站 Cookie 加载图片。

对外导出服务必须检查控制器身份和允许的命令，只开放合理的浏览与播控能力；不得通过会话公开 Cookie、账号配置或数据库路径。未登录或音源失效时返回明确错误，并引导用户打开应用处理。

## 真机验证计划

1. 记录机型、ROM 区域、完整系统与 Android 版本、原子随身听版本；不从“OriginOS 7”推断底层 Android 版本。
2. 构建最小原型：两首可控音频、一个歌单、完整元数据与媒体库服务。先排除 B 站网络和账号干扰。
3. 用测试 MediaBrowser 客户端验证服务能被发现、连接、浏览和点播；检查媒体会话及服务状态，证明应用侧标准实现有效。
4. 验证系统通知栏、锁屏和耳机按钮；记录前后台、熄屏、音频焦点中断及切歌行为。
5. 打开原子随身听及相关系统设置，检查是否出现应用、是否只在播放后出现、是否能展示封面和切歌、停止后是否保留入口。设置路径以该手机实际界面为准。
6. 分别测试停止后恢复、从最近任务划走、进程被回收、重启手机后的行为。用户“强行停止”单独记录，不等同正常进程回收。
7. 再替换为 B 站实际音频，复测地址过期、登录失效、断网重连及锁屏连续播放。

结果表按“系统标准播控 / 原子随身听当前会话 / 音源入口 / 歌单浏览 / 冷启动 / 原子岛”分别记录通过、失败、不可用或未测试，并附版本号，避免笼统标注“已适配 OriginOS”。

## 若标准实现后仍无法出现

先根据日志区分服务未正确发布、会话元数据不全、系统设置限制与厂商过滤。若其他标准客户端正常而原子随身听仍不展示，准备最小 APK、包名、版本信息和复现步骤，通过 vivo 开发者支持确认：

- OriginOS 7 是否支持普通第三方音乐应用自动发现，采用何种接口；
- 是否有开放 SDK、合作申请、应用审核或包名准入；
- 原子随身听当前会话展示、音源列表、歌单浏览和原子岛是否使用不同规则。

以上仅为待咨询问题，尚未发送。若需合作准入，可继续交付标准媒体适配；专用入口依赖厂商确认，不阻塞 Windows 开发。
